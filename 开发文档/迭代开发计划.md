## 🔐 Iteration 1: 后端基础 + 认证系统 (1.5天)

### 目标
实现完整的用户认证系统，包括注册、登录、JWT验证。

### 指令列表

#### 1.1 创建认证控制器
```
创建文件: api/controllers/authController.js

实现以下功能：
- POST /api/auth/register - 用户注册（email, username, password验证，bcrypt加密）
- POST /api/auth/login - 用户登录（验证密码，返回JWT token）
- GET /api/auth/me - 获取当前用户信息（需要JWT验证）
- POST /api/auth/refresh - 刷新token
```

#### 1.2 创建认证路由
```
创建文件: api/routes/auth.js

定义路由：
- POST /register -> authController.register
- POST /login -> authController.login
- GET /me -> authenticate middleware -> authController.me
- POST /refresh -> authController.refresh

在 server.js 中引入：
app.use('/api/auth', authRoutes);
```

#### 1.3 创建错误处理中间件
```
创建文件: api/middleware/errorHandler.js

实现功能：
- 统一错误响应格式
- 开发环境显示详细错误栈
- 生产环境隐藏敏感信息
- 记录错误日志
```

#### 1.4 创建验证中间件
```
创建文件: api/middleware/validation.js

实现功能：
- 邮箱格式验证
- 密码强度验证（最少8位）
- 用户名验证（3-20字符，字母数字）
- 通用字段验证函数
```

#### 1.5 测试认证流程
```
使用 Postman 或 curl 测试：

1. 注册新用户
POST http://localhost:3000/api/auth/register
{
  "email": "newuser@test.com",
  "username": "newuser",
  "password": "password123"
}

2. 登录获取 token
POST http://localhost:3000/api/auth/login
{
  "email": "newuser@test.com",
  "password": "password123"
}

3. 使用 token 获取用户信息
GET http://localhost:3000/api/auth/me
Authorization: Bearer <token>
```

### 验收标准

## 🤖 Iteration 3: AI生成系统 + 任务队列 (2.5天)

### 目标
集成 GLM-4 API，实现词汇内容的 AI 生成，配置 BullMQ 任务队列。

### 指令列表

#### 3.1 创建 GLM AI 服务
```
创建文件: api/services/ai/glmClient.js

实现功能：
- 初始化 GLM 客户端（apiKey, baseURL）
- chat(messages, options) - 调用 GLM-4 API
- 错误处理和重试机制
- Token 使用统计
```

#### 3.2 创建词汇生成服务
```
创建文件: api/services/ai/wordEntryGenerator.js

实现功能：
1. generateWordContent(wordEntry)
   - 构建提示词（使用 03 文档中的模板）
   - 调用 GLM API
   - 解析 JSON 响应
   - 验证内容结构
   - 返回 contentJson

2. 提示词模板应包含：
   - 词汇基础信息（word, pinyin, english, hskLevel）
   - 需要生成的内容结构（Quick Learn + Deep Dive + Practice）
   - 格式要求（JSON 格式）
```

#### 3.3 配置 BullMQ + Redis
```
创建文件: api/services/queue/queueManager.js

实现功能：
1. 初始化 Redis 连接（使用 REDIS_URL）
2. 创建生成队列（generationQueue）
3. 添加任务到队列
   - addWordGenerationTask(wordEntryId, priority)
   - addBatchWordGenerationTasks(wordEntryIds, batchId)
4. 获取队列状态
   - getQueueStatus()
   - getBatchProgress(batchId)
```

#### 3.4 创建 Worker 进程
```
创建文件: api/workers/generation-worker.js

实现功能：
1. 监听 generationQueue
2. 处理词汇生成任务：
   - 从数据库获取 WordEntry
   - 调用 wordEntryGenerator.generateWordContent()
   - 更新 WordEntry 的 contentJson 和状态
   - 更新 GenerationTask 状态
3. 错误处理：
   - 记录错误信息
   - 重试机制（最多 3 次）
   - 失败后更新状态为 ERROR
4. 进度报告：
   - 更新批次进度
   - 记录日志
```

#### 3.5 创建管理后台词汇生成 API
```
创建文件: api/controllers/admin/wordGenerationController.js

实现功能：
1. POST /api/admin/words/import - 批量导入词汇（CSV）
   - 解析 CSV 文件
   - 创建 WordEntry 记录（状态：PENDING_IMPORT）
   - 返回导入结果

2. POST /api/admin/words/generate - 批量生成内容
   - 获取 PENDING_IMPORT 或 ERROR 状态的词汇
   - 创建批次（GenerationBatch）
   - 为每个词汇创建 GenerationTask
   - 添加任务到队列
   - 返回批次 ID

3. GET /api/admin/words/generate/:batchId - 获取生成进度
   - 查询批次状态
   - 统计完成/失败/进行中的任务数
   - 计算进度百分比
   - 预估剩余时间

4. POST /api/admin/words/generate/:batchId/cancel - 取消批次
   - 标记批次为 CANCELLED
   - 从队列中移除待处理任务
```

#### 3.6 创建队列管理 API（10个端点）
```
创建文件: api/controllers/admin/queueController.js

实现功能（根据 02 文档）：
1. GET /api/admin/queue/status - 获取队列详细状态
2. POST /api/admin/queue/batches/:batchId/cancel - 取消批次
3. GET /api/admin/queue/jobs/:jobId - 获取任务进度
4. GET /api/admin/queue/batches - 获取批次列表
5. POST /api/admin/queue/pause - 暂停队列
6. POST /api/admin/queue/resume - 恢复队列
7. DELETE /api/admin/queue/jobs/:jobId - 删除/重试任务
8. POST /api/admin/queue/clean - 清理历史任务
9. GET /api/admin/queue/metrics - 获取队列指标
10. GET /api/admin/queue/failed - 获取失败任务列表
```

#### 3.7 启动 Worker 进程
```
在 package.json 中添加脚本：

在开发时需要同时运行：
Terminal 1: npm run dev (API server)
```
